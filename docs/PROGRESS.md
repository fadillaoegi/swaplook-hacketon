## Credit protection, demo model, side-by-side try-on — 19 October 2026

User asked for roadmap priorities 1–3 (user testing deliberately deferred until deploy).

- **Credit protection:** migration `004_generation_ledger.sql` adds a durable ledger of actual provider generations (backfilled from existing jobs), so limits survive session media cleanup. `Service.PreviewFor` reserves a ledger slot under a PostgreSQL advisory lock and enforces daily, total and per-client limits (`PREVIEW_DAILY_LIMIT`=25, `PREVIEW_TOTAL_LIMIT`=150, `PREVIEW_CLIENT_DAILY_LIMIT`=5 by default; windows reset at UTC midnight = 07:00 WIB). Client keys are HMACs of the caller address with a per-process random salt; `X-Forwarded-For` is used only with `TRUST_PROXY=true`. Quota exhaustion returns 429 `code=quota` and never reaches the provider. Session state exposes remaining previews; merchant studio shows generations, remaining today/total, success/failure/reuse counts and average render time.
- **Request rate limits:** in-memory per-client limiter (sessions 30/h, uploads 15/h, merchant 30/min, other writes 120/min) returns 429 `code=rate_limited`. Single-instance only; documented in code.
- **Demo model:** optional `DEMO_MODEL_IMAGE` (Compose: `CONTAINER_DEMO_MODEL_IMAGE`, mount `.data/models`), validated/normalized at startup, served at `GET /api/demo-model`. In actual mode shoppers can pick "Demo model" instead of uploading. Identical demo-model+SKU requests reuse an earlier successful provider result (copied per session, labelled "YOUCAM · REUSED AI PREVIEW", not counted against limits or session slots).
