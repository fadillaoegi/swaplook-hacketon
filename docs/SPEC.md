# Implementation specification

Backend: Go standard HTTP server, pgx PostgreSQL adapter, SQL migrations embedded in the binary. Domain models and deterministic filtering have no infrastructure imports. Application services own repository, renderer and private storage ports. HTTP adapters validate bodies, session ownership, origin and merchant credentials. Composition root reads server environment only.

Frontend: React/Vite/TypeScript/Tailwind. Domain DTOs → gateway interface → fetch adapter → presentation state/hooks. The server remains authoritative for shortlist, stock and merchant authorization. Vite proxies /api to the Go server; deployment requires the same origin and an HTTPS reverse proxy. No hosted deployment is included yet.

Persistence: products, variants, sessions, shortlists, decisions, photo sources, render jobs. Session cookies have 256-bit random values, HttpOnly/SameSite=Lax, 24-hour validity. Merchant token is never persisted in browser storage. All events in this prototype have demo=true. Foreign keys bind jobs and choices to server shortlists. Session-row locks serialize shortlist/selection and job budget updates. Stock updates and final decisions lock the variant row. Final choices preserve a snapshot and do not decrement inventory.

Images: private local storage in development, behind a Storage port. Uploaded photos are normalized to PNG to strip embedded metadata. Upload input is bounded at 8 MiB; normalized provider input must stay below 10 MiB. Provider result input permits 10 MiB with normalized private output below 20 MiB. Files are session-owned; no static private directory. Deletion removes photos/results and marks jobs deleted while retaining consumed preview slots; session expiration prevents access. Startup and 30-minute periodic cleanup remove expired media/job records while retaining synthetic decisions. Failed deletion retains ownership for retry. Catalog illustrations are original public fixtures. Actual YouCam requires matching licensed PNG/JPEG garment files per SKU in YOUCAM_GARMENT_DIR; illustrations are never silently submitted.

Rendering: explicit simulator or YouCam V4 adapter. Submit once after reserving a durable job; persist a known task ID with a bounded detached context even if the client disconnects. Ambiguous submission failure is 'unknown' and is never auto-resubmitted. Provider polling is spaced (10 seconds), bounded (60 automatic polls plus three explicit reconciliation checks), with a 90-second persisted lease preventing overlap. Only the current lease can complete a result. A timed-out task can complete through reconciliation without a new generation. Result files are downloaded server-side to private storage. No signed URLs or provider task IDs are exposed to the browser. Known task errors are terminal; network polling errors retain the job. No automatic generation retry.

API: GET /api/health, GET /api/catalog; POST/GET/DELETE /api/session; POST /api/shortlist; POST /api/decisions; POST /api/photos; DELETE /api/photos; POST /api/previews; POST /api/previews/{id}/poll; POST /api/previews/{id}/reconcile; GET /api/images/{id}; GET /api/merchant/summary; PATCH /api/merchant/stock. Optional STATIC_DIR serves only the built frontend, shopper/merchant HTML routes and allowlisted public assets; private files, source maps, directory listings and API misses do not receive the SPA document. Documents are revalidated, hashed build assets are cached immutably, and a self-only content policy is applied. See README for execution and environment.

Deployment gaps: production merchant identity, rate limiting across IPs, shared object storage, HTTPS, backup/expiry operations, public demo and real API evidence must be completed before public launch. Development bind defaults to loopback.
